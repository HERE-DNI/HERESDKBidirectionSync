    <h1 class="cover"><span>Map</span><wbr></wbr><span><span>Matcher</span></span></h1>
    <div class="platform-hinted " data-platform-hinted="data-platform-hinted"><div class="content sourceset-dependent-content" data-active="" data-togglable=":modules:dokkaHtml/release"><div class="symbol monospace"><span class="token keyword">class </span><a href="index.html">MapMatcher</a> : <a href="../../com.here/-native-base/index.html">NativeBase</a></div><p class="paragraph">This class provides map-matching functionality. It determines whether a location can be matched to a nearby road network and provides additional OCM map data for that location.</p><p class="paragraph"><strong>Note:</strong> This is a <strong>beta</strong> release of this feature. There may be bugs and unexpected behaviors. Related APIs may change in future releases without a deprecation process.</p><p class="paragraph">A <code class="lang-kotlin">MapMatcher</code> maintains an internal state across location updates. This helps to check if the match is consistent with previous matches or if an unrealistic jump occurred due to low accuracy of the provided location.</p><p class="paragraph">A <code class="lang-kotlin">MapMatcher</code> requires OCM tile data, either through caching, prefetching, or installed <code class="lang-kotlin">Region</code> data. If the necessary tiles are not found, an online request is initiated. Note that in such cases, the download is triggered silently in the background, and <code class="lang-kotlin">null</code> is returned immediately.</p><p class="paragraph">The <code class="lang-kotlin">MapMatcher</code> supports two layer configurations for retrieving segment geometry data:</p><ul><li><p class="paragraph"><strong>Rendering layer (</strong><code class="strong lang-kotlin"><strong>LayerConfiguration.Feature.RENDERING</strong></code><strong>)</strong>: Enabled by default. If your application uses map rendering or <code class="lang-kotlin">MapView</code> components, using this layer is recommended.</p></li><li><p class="paragraph"><strong>eHorizon layer (</strong><code class="strong lang-kotlin"><strong>LayerConfiguration.Feature.EHORIZON</strong></code><strong>)</strong>: Not enabled by default. It encodes segment geometries outside the rendering layer groups to reduce the amount of downloaded data. Use the eHorizon layer when:</p></li><li><p class="paragraph">No <code class="lang-kotlin">MapView</code> is used in your application.</p></li><li><p class="paragraph">Only the eHorizon layer is used in your application.     In these cases, using the eHorizon layer will reduce the required data to download. If the rendering layer is enabled, it will increase the required data to download.</p></li></ul><p class="paragraph"><strong>Important</strong>: If <code class="lang-kotlin">useRenderingLayers</code> is set to <code class="lang-kotlin">false</code> without properly enabling the eHorizon layer, it may produce incorrect results. Layer configuration is especially important when prefetching or installing region data. Missing data will be downloaded online automatically as needed.</p><p class="paragraph">If your hardware supports pitch and high precision altitude information and you want to use them in the <code class="lang-kotlin">MapMatcher</code> to improve map-matching, then enable the <code class="lang-kotlin">LayerConfiguration.Feature.ADAS</code> layer:</p><ol><li><p class="paragraph">Turn on the <code class="lang-kotlin">ADAS</code> layer via <code class="lang-kotlin">LayerConfiguration.enabledFeatures</code> (it will increase data consumption).</p></li><li><p class="paragraph">If available, set <code class="lang-kotlin">location.pitchInDegrees</code>, <code class="lang-kotlin">location.coordinates.altitude</code> and <code class="lang-kotlin">location.verticalAccuracyInMeters</code>.</p></li><li><p class="paragraph">In case of issues, please contact your HERE representative.</p></li></ol></div></div>
